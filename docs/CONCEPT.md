# 概念文档：省力 —— 一个为「没精力、坚持不了」的人造的应用

> 状态：概念草案（供产品/工程对接）
> 日期：2026-08-30
> 一句魂：**你不需要坚持。你需要的是"不用坚持也能完成"的方法。**

---

## 0. 一句话定位

一个**替你省精力**的应用。它不教你怎么打扫、怎么做饭、怎么自律——
它只做一件事：**在你没电的时候，把你今天唯一需要做的那件小事，摆到你面前，并且不让你愧疚。**

- 家的省力 = 断舍离（现有 `server/rules.py` / `agent.py` / `prompts.py` 体系）
- 身体的省力 = 三餐（现有 `meals.py` / `meal_rules.py` / 盒马清单）
- 两者共用同一个魂：**进出平衡、时间轴复盘、零决定成本。**

---

## 1. 사연（起源故事）—— 它为什么存在

这个产品不是从"断舍离理论"出发的，是从一个具体的人出发的：

> **"我日常生活就是总没精力打扫，一直无法坚持做饭，才做的这个。"**

用户不是懒，是**没精力**；不是不会，是**坚持不了**。市面上所有整理 App 和做饭 App
都默认你"有精力、有动机"——打卡、连击、宏大计划、更多菜谱。它们的前提就错了：
**目标用户电量不足，任何要求"多做一个动作"的设计，都是在伤口上撒盐。**

这个应用的存在理由只有一个：**让一个没精力、坚持不了的人，今天也能完成最小的一步，
且不因此愧疚。**

---

## 2. 本质诊断 —— 真正的敌人

| 表象 | 真相 |
|---|---|
| 房间乱 | 不是不知道方法，是没力气启动 |
| 三餐坚持不了 | 不是不会做，是**决定成本 + 失败成本**压垮了意志 |
| "我坚持不了" | 自我审判的框架——愧疚消耗最后一点电 |

目标用户的稀缺资源不是时间，是**精力**。产品的一切设计以「精力」为计量单位。

### 核心不变量

> **用户今天的精力余额是变量，产品必须自适应。**
> 精力足 → 可以给 20 分钟任务；精力枯 → 只给 5 分钟任务 + 一顿不用选的饭 + 一句不指责的话。

---

## 3. 框架反制 —— 「坚持」是陷阱

"坚持"是个惯性框架，它预设你需要意志力，然后意志力崩了 → 愧疚 → 更没力 → 放弃。

**这个产品不靠坚持。** 它靠把阻力降到零：

- 断舍离的本义就是**反意志力**：不是"你得更自律"，是"断绝不需要的进来，剩下的自然流动"。
- 三餐的本义同样**反意志力**：不是"你得更自律地做饭"，是"让不费劲地吃上饭成为默认选项"。

一句话传播物：**"你不需要坚持。你需要的是'不用坚持也能完成'的方法。"**

---

## 4. 核心测试题 —— 唯一评判标准

从今往后，每个功能只回答一道题：

> **这个功能是消耗用户的精力，还是替用户省精力？**

省 → 收。耗 → 拒。

---

## 5. 惯性批判 —— 该杀的清单

| 惯性动作 | 判定 | 替代 |
|---|---|---|
| 连续打卡 / 连击 / 绿点 | **杀** | 断了一天 = 全盘皆输 = 愧疚 = 卸载。改用"90 天观察期"：今天不做没关系，到时再回看 |
| "打扫房间"式宏大任务 | **杀** | 原子化：最小一步。5 分钟能完成、失败零代价 |
| "从第一间房开始"的全屋计划 | **杀** | 只做鞋柜第三层、只扔三罐过期调料 |
| 更多菜谱 | **杀** | 降低今晚的决定成本：不用选、照着买、便当锁死 |
| 干净整洁的"成品照片"作为目标 | **改造** | 目标是"我做了一点"，不是"房子像样板间" |

---

## 6. 一体化设计

### 6.1 产品脸：三格电，不是仪表盘

首页不是七个功能入口，是**一格电量表**。

- 打开即问：**"今天还剩多少力气？"**（三格电：满格 / 半格 / 没电）
- 电量决定这一屏给什么：
  - 满格 → 一个 15 分钟任务 + 一餐可选菜单
  - 半格 → 一个 5 分钟任务 + 直接给今天吃什么
  - 没电 → 一个 2 分钟任务（或"今天就歇着，明天再说"）+ 一句话"你已经做得很好了"

**三格电是这个产品的签名元素**——别的整理/做饭 App 永远不会有，因为它默认你没电。

### 6.2 最小一步（产品哲学，不只是功能）

- 任务原子化到"5 分钟能完成、失败零代价"
- 每个任务都带 `est_minutes`（现有字段），且 UI 必须显式标注"约 X 分钟"
- 完成即加分，不完成不扣分——**没有负数**

### 6.3 加分法升格为评分

现有 `danshari_score` 语义是"代谢率"——保留规则引擎（防幻觉、LLM 不可覆盖，这是好架构），
但**对外表达要从"扣分制"翻成"加分制"**：

- 用户看到的不是"你房间只有 40 分"，而是"这周你完成了 3 件最小的事，比上周多 1 件"
- 评分衡量的是**努力轨迹**，不是干净程度。干净是结果，努力是值得被看见的东西
- 原则：**不制造"你不会整理"的自责。** 局面不全是用户的错

### 6.4 反打卡：90 天观察期作为核心机制

- 犹豫的物品 → 90 天观察期，到期温柔提醒复查（现有 `QUARANTINE_DAYS = 90`）
- 语义从"审判庭"（现有代码注释）调为**"不急着决定"**：拿不定主意 = 被允许，不是问题
- 观察期是**时间轴**机制：只有坚持到期的用户才会遇到它——这是护城河，不是负担

### 6.5 三餐：身体的省力

- "无法坚持做饭"的解法不是菜谱，是**决定成本 + 失败成本归零**
- 现有资产全部成立：自动生成三餐、拳头份量、盒马五分区清单、bento 锁（做好即锁，不许推翻）
- 叙事从"我要坚持做饭"改成"**吃上饭这件事，不用我操心**"

### 6.6 视觉方向（基于现有设计系统，不是重写）

现有底子成立，保留：和纸白 `#faf9f6` × 青竹绿 `#3e6b52` × 朱印 `#b3402a`、
宋体印记、印章/纸张质感。在此基础上做三件事：

1. **留白优先**：一个教人 7·5·1 法的应用，自己的界面必须按它教的来——
   看不见的空间≤7 成，界面上的"杂物"（按钮/入口/文字）只留必要。
2. **决策最少化**：一屏只推一个动作，不排多个入口。
3. **签名元素 = 三格电**：电量表是全界面唯一被记住的东西，其余保持安静克制。
   字体、色彩、印章全部退后，让"电量"自己说话。

## 7. 现有功能 → 省力 映射表（不是重写，是改名 + 重指）

| 现有功能 | 它省的力 | 需要做的动作 |
|---|---|---|
| 拍照→自动识别物品 | 省记录的力 | 保留 |
| 二段式识别 + 待确认 | 省误判的力 | 保留，确认动作尽量一键 |
| 评分规则引擎（防幻觉） | 省不信任的力 | 保留，对外翻成加分制表达 |
| 90 天观察期 | 省愧疚的力 | 语义从"审判庭"调为"不急着决定" |
| 三餐自动生成 + 换菜 | 省决定的力 | 保留 |
| 盒马五分区清单 | 省执行的力 | 保留 |
| bento 锁 | 省反悔的力 | 保留 |
| 加分法语气、最小行动建议 | 省情绪的力 | **升格**为评分与首页的表达 |
| 批量上传 / 计划加图 / 批次历史 | 省重复操作的力 | 保留，退到抽屉，不当脸 |

**结论：约 80% 是既有资产的重新拧紧，不是新造。**

---

## 8. 边界 —— 拒绝清单

| 候选扩展 | 判定 | 理由 |
|---|---|---|
| 日历 / 日程 | **拒** | 需要用户维护 = 耗力 |
| 记账 / 理财 | **拒** | 需要用户录入 = 耗力 |
| 通用 todo 清单 | **拒** | 要求自律 = 耗力 |
| 健康数据 / 运动打卡 | **拒** | 打卡即惯性税 |
| 更多菜谱 / 更多功能入口 | **拒** | 决定成本上升 = 耗力 |

**凡是省力的收，凡是耗力的拒。** 用户已经没电了，这是全产品最高原则。

---

## 9. 亮相策略

- **不需要新功能就能亮相**：概念升级、首页重构（三格电）、叙事重排——全是现有零件重新拧。
- **时机三问**：
  1. 行业注意力空窗在哪？——所有人都在堆"生成更多"；我们反着亮"少、省力、时间轴"。
  2. 多维牌能一次打出吗？——隐私（照片不出本机）+ 省力概念 + 90 天时间轴 = 一张牌，一次亮。
  3. 规模-创新反比此刻站在我们这边吗？——站在。大厂抄不了"省力"，因为那需要
     规则引擎 + 跨时间的用户承诺；他们只能抄功能，抄不了概念。
- **一句话亮相语**："你不需要坚持。你需要的是'不用坚持也能完成'的方法。"

---

## 10. 里程碑（阶段化）

- **M0 重指（不写新代码）**：把"省力"写进系统提示词的语气层；加分法表达调整；
  观察期语义从"审判庭"调为"不急着决定"。≈ 半个周末。
- **M1 三格电首页（核心）**：首页重构为电量表驱动的单动作入口；任务显式标"约 X 分钟"；
  反打卡（隐藏连击类视觉）。≈ 一个 sprint。
- **M2 时间轴账本**：物品跨时间稳定身份（同一样东西上周在、这周在吗？90 天后走了吗？）；
  家的账 + 身体的账共用一条时间轴。≈ 一到两个 sprint。
- **M3 名字与叙事**：确定产品名（魂是"省力"，名字由用户定，不在本文档内替你决定）。

---

## 11. 风险

1. **自己别又贪**：省力概念诱惑你扩展（现金流代谢、时间代谢……全是代谢）。
   **停。** 家 + 身体，够了。扩展 = 把注意力切成八瓣 = 什么都做不成。
2. **加分制可能被读成"不真实"**：要诚实——任务完成才算加分，不许给用户"云表扬"。
3. **三格电可能被用户当摆设**：必须真的改变内容供给，不能只是 UI 装饰。
